Setup 1/2 • Ferramenta Principal

Instalar o Google Antigravity CLI (agy)

O Antigravity CLI (agy) instala-se num único comando e coloca o binário em ~/.local/bin/agy:

1. Instalar por Sistema Operativo

# Linux, macOS ou WSL:
curl -fsSL \
  https://antigravity.google/cli/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"

# Windows (PowerShell):
irm https://antigravity.google/cli/install.ps1 | iex

Recarregue o terminal (source ~/.bashrc ou ~/.zshrc) para atualizar o PATH.

2. Autenticar com API Key (Script Automático)

# Instala o agy + pede a GEMINI_API_KEY:
./scripts/install-antigravity.sh
source ~/.bashrc && agy
  • Define "modelProvider": "gemini" em ~/.gemini/antigravity-cli/settings.json.
  • Guarda export GEMINI_API_KEY="..." no ~/.bashrc / ~/.zshrc.
  • Guia oficial CLI: https://antigravity.google/docs/install/?tab=cli
Documentação Oficial: Consulte todas as flags e opções em https://antigravity.google/docs/cli/reference ou execute agy --help.

1. Fundamentos

De Autocompletar Código para Pair Programming Agêntico

O sucesso com agentes de IA não depende de "prompts mágicos", mas sim de Engenharia de Contexto e de Guardrails Determinísticos versionados no Git.

Dimensão Uso Ad-Hoc de IA (Chat / Copilots) Engenharia AI-First com Antigravity (agy)
Memória do Projeto Repetida manualmente pelo programador em cada conversa. Codificada em AGENTS.md, ADRs (docs/adr/) e Skills no Git.
Procedimentos Complexos O modelo tenta adivinhar passos de migração ou deploy. Procedimentos passo a passo em .agents/skills/<nome>/SKILL.md.
Qualidade e Segurança Revisão humana manual de erros de lint ou comandos arriscados. Automatizada com Lifecycle Hooks (PreToolUse / PostToolUse).
Acesso a Ferramentas Copiar e colar logs, esquemas SQL ou tickets para o chat. Ligação direta e governada via Servidores MCP (mcp_config.json).
Regra de Ouro: Se tiver de corrigir o agente duas vezes sobre a mesma convenção do projeto, essa regra deve ser gravada imediatamente num ficheiro AGENTS.md, numa Skill ou num Hook (usando /learn).
2. Antigravity CLI

Dominar o Antigravity CLI (agy) no Terminal

Flags de Sessão e Raciocínio

# Iniciar sessão interativa no diretório atual
agy

# Continuar a conversa mais recente ou por ID
agy -c
agy --conversation <id>

# Definir modo de execução e esforço de raciocínio
agy --mode plan --effort high

# Adicionar diretorias extra ao workspace
agy --add-dir ../shared-lib

# Executar com sandbox de terminal ativo
agy --sandbox

Execução Não-Interativa & Subcomandos

# Modo Print (-p): ideal para CI/CD e scripts
agy -p "Check failing unit tests"

# Saída estruturada em JSON com validação de Schema
agy -p "Audit dependencies" \
  --output-format json \
  --json-schema ./schema.json

# Subcomandos de Gestão do Ecossistema
agy mcp list            # Gerir servidores MCP
agy plugin list         # Gerir plugins instalados
agy models              # Listar modelos disponíveis
agy agents              # Listar agentes disponíveis
--mode plan

Ideal para desenhar soluções complexas sem alterar ficheiros antes da aprovação.

--mode auto

Equilíbrio padrão: executa ações seguras e pede permissão em operações sensíveis.

--mode accept-edits

Aceita edições de ficheiros automaticamente, mantendo controlo sobre comandos de sistema.

Comandos Slash (/) para Orquestrar o Fluxo de Trabalho

Dentro da interface interativa (TUI) do agy, os comandos / ativam comportamentos especializados:

Comando Objetivo Momento Recomendado de Utilização
/grill-me Entrevista Interativa de Requisitos Antes de desenhar ou programar. O agente faz perguntas para eliminar ambiguidades e alinhar decisões de arquitetura.
/plan Planeamento Estruturado Passo a Passo No início de funcionalidades multi-ficheiro ou refatorizações estruturais.
/boost Pensamento Profundo & Verificação Rigorosa Problemas complexos de concorrência, arquitetura ou bugs difíceis de diagnosticar.

/teamwork Equipa de Subagentes Autónomos Projetos de grande dimensão que beneficiam de divisão de trabalho em paralelo.
/learn Cristalização de Conhecimento Sempre que corrige o agente ou resolve uma configuração complexa que deve ficar persistida para o futuro.
/compact Compactação da Janela de Contexto Quando a conversa fica longa; resume o histórico preservando o estado essencial.
/schedule • /browser Agendamento Cron • Automação Web Para tarefas periódicas em segundo plano ou testes interativos no navegador.
3. Estrutura de Projeto

Estrutura de Diretorias e Ficheiros Recomendados

my-ai-ready-project/
├── AGENTS.md                 # Regras globais
├── docs/                     # Docs de arquitetura
│   ├── architecture.md       # Mapa do sistema
│   ├── conventions.md        # Padrões e testes
│   └── adr/                  # Decisões (ADRs)
│       └── 0001-stack.md
├── .agents/                  # Personalização (Git)
│   ├── skills.json           # Registo de skills
│   ├── plugins.json          # Registo de plugins
│   ├── hooks.json            # Ciclo de vida
│   ├── scripts/              # Scripts dos hooks
│   ├── skills/               # Skills on-demand
│   │   └── db-migration/
│   │       ├── SKILL.md      # YAML + instruções
│   │       ├── scripts/      # Validação
│   │       ├── examples/     # Exemplos
│   │       ├── resources/    # Templates
│   │       └── references/   # Manuais detalhados
│   └── plugins/              # Plugins da equipa
└── apps/
    ├── api/AGENTS.md         # Regras Backend
    └── web/AGENTS.md         # Regras Frontend

Porquê esta estrutura?

  • Partilha via Git (VCS): A pasta .agents/ (ou .agent/) na raiz do projeto garante que toda a equipa partilha as mesmas Skills, Hooks e Plugins assim que faz git clone.
  • Hierarquia Contextual: O agente percorre o caminho desde o ficheiro que está a editar até à raiz do repositório, combinando o AGENTS.md local com o da raiz.
  • Documentação Viva (docs/): Manter ADRs e architecture.md atualizados evita que o agente proponha padrões incompatíveis com decisões passadas.
Global vs. Projeto: Configurações pessoais da sua máquina ficam em ~/.gemini/config/ (e as opções da CLI em ~/.gemini/antigravity-cli/settings.json). Tudo o que é da equipa fica em .agents/.
4. Sistema de Personalização

Os 5 Pilares de Personalização do Antigravity

Escolha o mecanismo certo consoante o problema que pretende resolver:

Tipo Ficheiro / Diretoria Âmbito de Ativação Quando Utilizar
Rules AGENTS.md ou GEMINI.md Contextual e Hierárquico (sempre ativo no diretório) Impor estilo de código, restrições de arquitetura, comandos de teste e proibições permanentes.
Skills .agents/skills/<nome>/SKILL.md On-Demand (Divulgação Progressiva) Ensinar fluxos de trabalho passo a passo, runbooks, criação de migrações ou novos módulos.
Hooks .agents/hooks.json Evento do Ciclo de Vida (Síncrono) Executar validações determinísticas: bloquear comandos destrutivos, correr linters ou forçar testes antes de parar.
MCP Servers mcp_config.json Integração de Ferramentas Ligar o agente a sistemas externos (PostgreSQL, SQLite, GitHub, Jira, Grafana, APIs internas).
Plugins .agents/plugins/<nome>/plugin.json Pacote Unificado (Bundle) Agrupar Skills, Rules, Hooks e MCP numa unidade partilhável que pode ser ligada/desligada de uma só vez.
Ordem de Prioridade de Descoberta (da mais alta para a mais baixa):
1. Workspace (.agents/) → 2. Configs Declaradas (skills.json / plugins.json) → 3. Global (~/.gemini/config/) → 4. Built-in → 5. Configs Globais Declaradas.
5. Gestão de Contexto

Orçamento de Contexto e Divulgação Progressiva

Encher a janela de contexto com milhares de linhas de instruções degrada a atenção do modelo. O Antigravity resolve isto com Divulgação Progressiva (Progressive Disclosure):

Regras (AGENTS.md / GEMINI.md)

  • Sempre Ativas no seu diretório: São carregadas automaticamente quando o agente trabalha nesse diretório.
  • Limite por Ficheiro: 24 KB (24.000 bytes, após expandir inclusões @[label](path)).
  • Orçamento Agregado de Regras: 20.000 tokens dedicados.
  • Degradação Graciosa: Se exceder o orçamento, as regras excedentes passam de texto inline para ponteiros de ficheiro lidos sob pedido.
  • Deduplicação: Cada ficheiro de regra é injetado no máximo uma vez por conversa.

Skills (SKILL.md) — Poupança de Tokens

  • Passo 1 (Injeção Leve): No início da conversa, apenas o name e a description de cada Skill são incluídos no prompt do sistema.
  • Passo 2 (Ativação Sob Pedido): O corpo de SKILL.md só é lido quando a tarefa do utilizador corresponde à descrição da Skill.
  • Passo 3 (Referências Profundas): Ficheiros pesados em references/ ou examples/ só são lidos pelo agente se o passo específico os exigir.
Anti-Padrão Comum: Colocar manuais de 50 páginas dentro do AGENTS.md da raiz. Mantenha o AGENTS.md enxuto (< 150 linhas) e mova procedimentos específicos para .agents/skills/!
6. Deep Dive: Rules

Como Escrever Ficheiros AGENTS.md Eficazes

Exemplo: AGENTS.md na Raiz

# Workspace Engineering Rules

## Build, Lint & Test Commands
- Install: `pnpm install`
- Unit test (1 file): `pnpm vitest run <path>`
- Typecheck: `pnpm -r typecheck`
- Lint & Format: `pnpm check`

## Architecture & Boundaries
- `packages/shared`: pure domain types & Zod.
- `apps/web` never imports from `apps/api`.
- DB changes require the `db-migration` skill.

## Coding Conventions
- Use explicit return types on exports.
- Never commit secrets or `.env` files.

Exemplo: apps/api/AGENTS.md (Contextual)

# Backend API Rules (Python / FastAPI)

## Local Commands
- Single test: `pytest tests/unit/<file> -q`
- Lint: `ruff check src/ && ruff format --check`

## API Guidelines
- Endpoints must use Pydantic v2 models.
- Use `Depends` for database sessions.
- Raise domain errors from `src.core.errors`,
  never raw HTTP 500.

Checklist de Qualidade para Rules

  • Dê sempre o comando para correr um único ficheiro de teste (feedback rápido).
  • Não use YAML frontmatter em ficheiros AGENTS.md / GEMINI.md autónomos.
6. Deep Dive: Skills

O que são as Skills (SKILL.md)?

As Skills são pacotes modulares que ensinam ao agente como executar um fluxo de trabalho específico da sua equipa com precisão e validação determinística.

Anatomia de uma Skill

.agents/skills/db-migration/
├── SKILL.md              # Obrigatório (YAML + Passos)
├── scripts/              # Opcional: Executáveis
│   └── validate-sql.sh
├── examples/             # Opcional: Exemplos
│   └── 001_users.sql
├── resources/            # Opcional: Templates
│   └── header.sql
└── references/           # Opcional: Docs extensos
    └── zero-downtime.md

Boas Práticas para Skills

  • Descrição na 3.ª pessoa: Especifique o que faz e quando deve ser ativada.
  • Scripts Executáveis: Encapsule comandos bash complexos em scripts/.
  • Passos de Validação: Termine sempre com um comando que comprove o sucesso.

Exemplo de SKILL.md

---
name: db-migration
description: >-
  Creates and validates zero-downtime SQL migrations.
  Use when the user asks to create, alter, or review
  database tables, columns, or indexes.
---

# Database Migration Skill

Follow these steps when creating a migration:

## 1. Preparation
1. Review [001_users.sql](./examples/001_users.sql).
2. If altering a table, read
   [zero-downtime.md](./references/zero-downtime.md).

## 2. Execution & Verification
1. Create SQL file in `apps/api/migrations/`.
2. Run validation script to check for table locks:
   `./.agents/skills/db-migration/scripts/validate-sql.sh`
6. Deep Dive: MCP

O que é um Servidor MCP (mcp_config.json)?

O Model Context Protocol (MCP) é um protocolo aberto que permite ao agente interagir de forma segura e padronizada com bases de dados, APIs e ferramentas externas.

Configuração (mcp_config.json)

Localização: Global em ~/.gemini/config/mcp_config.json ou empacotado num Plugin em plugins/<nome>/mcp_config.json.

{
  "mcpServers": {
    "local-sqlite-inspector": {
      "command": "python3",
      "args": [
        "./tools/local-mcp-server/server.py",
        "--db", "./data/dev.db"
      ],
      "env": {
        "DB_READONLY": "true"
      }
    },
    "company-observability": {
      "url": "https://mcp.internal.company.com/mcp"
    }
  }
}

Os 2 Transportes Suportados

1. Stdio Transport (Local)

O Antigravity inicia o executável localmente (command + args + env) e comunica via stdin / stdout. Ideal para ferramentas CLI locais, SQLite, scripts Python/Node.

2. Streamable HTTP Transport (Remoto)

Liga-se a um servidor remoto através do campo url (endpoint /mcp).
Nota: O transporte legado HTTP+SSE não é suportado diretamente; utilize endpoints Streamable HTTP ou uma bridge stdio.

Gestão rápida via CLI: agy mcp list, agy mcp add, agy mcp enable/disable.

6. Deep Dive: Hooks

Lifecycle Hooks (.agents/hooks.json)

Os Hooks executam comandos shell síncronos em eventos do ciclo de vida do agente. Recebem um payload JSON em stdin (chaves em camelCase) e devolvem JSON em stdout.

Evento Quando Dispara Ação Típica (stdout)
SessionStart Início de sessão Injetar contexto (injectSteps)
PreToolUse Antes de correr ferramenta decision: allow, deny, ask, force_ask
PostToolUse Após ferramenta Correr linter/formatter (devolve {})
PreInvocation Antes de invocar modelo Injetar ephemeralMessage
PostInvocation Após ferramentas terminationBehavior: force_continue
Stop Quando vai terminar decision: "continue" se testes falharem

Exemplo: .agents/hooks.json

{
  "command-safety-guard": {
    "PreToolUse": [
      {
        "matcher": "run_command",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/command-guard.sh",
            "timeout": 5
          }
        ]
      }
    ]
  },
  "post-edit-linter": {
    "PostToolUse": [
      {
        "matcher": "edit_file|write_file",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/post-edit-check.sh",
            "timeout": 15
          }
        ]
      }
    ]
  }
}

7. Metodologia

Como Criar e Manter Projetos com IA no Dia a Dia

Criar um Projeto do Zero (Greenfield)

  1. Entrevista de Alinhamento (/grill-me): Clarifique requisitos funcionais, casos-limite e stack antes de gerar código.
  2. Arquitetura & ADRs (/plan): Gere docs/architecture.md e o primeiro ADR em docs/adr/0001-...md.
  3. Fundação AI-First: Crie o AGENTS.md da raiz, configure o linter/test runner rápido e adicione hooks de segurança em .agents/hooks.json.
  4. Fatias Verticais Pequenas: Construa e teste uma funcionalidade de ponta a ponta de cada vez, fazendo commits frequentes.

Manter e Escalar Projetos (Brownfield)

  1. Subagentes de Pesquisa (research): Peça para investigar fluxos complexos num subagente de leitura sem poluir o contexto principal.
  2. Isolamento em Worktrees (self): Execute refatorizações paralelas em subagentes com workspace branch ou share.
  3. Melhoria Contínua (/learn): Sempre que corrigir um comportamento do agente, transforme a correção numa regra em AGENTS.md ou numa nova Skill.
  4. Higiene de Contexto (/compact): Compacte conversas longas ou inicie uma sessão limpa a cada nova funcionalidade.
Dica de Produtividade: O agente é tão eficaz quanto o seu ciclo de feedback. Se o comando de teste demorar 0.5s e devolver erros claros, o agente corrige problemas autonomamente à primeira tentativa.

8. Code-Along: Deep Dive Exemplo 04

App Full-Stack de Reserva de Mesas (04-restaurant-reservation/)

Aplicação completa em Node.js (API REST zero-dependências) e React 19 + Vite, acompanhada de instruções detalhadas passo-a-passo para adicionar novas funcionalidades.

Arquitetura em 4 Camadas

Camada Ficheiros & Papel
1. Contrato packages/shared/contracts.json — Define timeSlots, zones, reservationStatuses e esquemas.
2. API Node.js apps/api/src/{validators,store,app}.js — Previne double-booking (409) e excesso de lotação (400).
3. Web React apps/web/src/{api.js,App.jsx} — Mapa interativo de mesas (T1–T6), formulário e tabela de reservas.
4. Guardrails IA Skill add-reservation-feature + verify-fullstack.sh + Hook PostToolUse (node --check).

Fluxo Passo-a-Passo para Adicionar Funcionalidades

  1. Contrato: Atualizar packages/shared/contracts.json (ex: campo occasion ou entidade WaitlistEntry).
  2. Backend: Validar em validators.js, persistir em store.js e expor rota em app.js.
  3. Testes: Adicionar testes de integração em apps/api/tests/api.test.js (npm --prefix apps/api test).
  4. Frontend React: Adicionar método em src/api.js e atualizar src/App.jsx.
  5. Verificação: Correr ./.agents/skills/add-reservation-feature/scripts/verify-fullstack.sh.
cd examples/04-restaurant-reservation
npm test      # Testes da API Node.js + Build React
